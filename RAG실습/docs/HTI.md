# Hierarchical Task Inventory (HTI): 카페 키오스크 자연어 주문

목표 0. **키오스크와 대화해 원하는 음료/디저트를 주문하고 결제를 완료한다**

> Plan 0: 1~3을 필요한 만큼, 순서 상관없이 반복 → 4 → 5.
> 6, 7은 어느 단계에서나 발생할 수 있다. 8은 독립적인 부가 task다.

```
0. 주문 완료하기
├── 1. 메뉴 정보 얻기
│   ├── 1.1 카테고리별 메뉴 목록 조회          "디저트 뭐 있어요?"
│   ├── 1.2 특정 메뉴 상세 정보 조회
│   │   ├── 1.2.1 설명                          "아인슈페너가 뭐예요?"
│   │   ├── 1.2.2 사이즈별 가격                  "아메리카노 중 사이즈 얼마인가요?"
│   │   ├── 1.2.3 칼로리·카페인                  "콜드브루 카페인 얼마나 돼요?"

│   ├── 1.3 메뉴 비교                           "아메리카노랑 카푸치노 중 뭐가 더 진해요?"
│   └── 1.4 판매 가능 여부 확인
│       ├── 1.4.1 품절                           "딸기 요거트 스무디 주세요"
│       └── 1.4.2 온도/사이즈 제약                "아이스 카푸치노 돼요?"
├── 2. 추천 받기
│   ├── 2.1 맛 선호 기반                         "달콤한 음료 추천해 주세요"
│   ├── 2.2 조건 기반 (카페인·칼로리·알레르기)     "카페인 없고 우유 안 들어간 거"
│   ├── 2.3 음료-디저트 페어링                   "아메리카노랑 어울리는 디저트?"
│   └── 2.4 상황 기반 (아이, 더운 날, 감기)        "애들이 마실 만한 거 있어요?"
├── 3. 옵션 문의 및 선택
│   ├── 3.1 사이즈            3.2 온도(HOT/ICE)
│   ├── 3.3 샷 추가 / 디카페인  3.4 시럽 추가        "라떼에 바닐라 시럽 추가할 수 있나요?"
│   ├── 3.5 우유 변경          3.6 휘핑·당도·얼음

├── 4. 장바구니 관리
│   ├── 4.1 담기
│   │   ├── 4.1.1 필수 옵션(사이즈·온도) 누락 시 되묻기 (slot filling)
│   │   └── 4.1.2 한 문장에 여러 메뉴 + 옵션 동시 주문
│   ├── 4.2 수량 수정          "그거 3잔으로 바꿔주세요"
│   ├── 4.3 삭제              "크루아상은 빼주세요"

├── 5. 결제

│   ├── 7.1 카페와 무관한 질문           "오늘 날씨 어때요?"

└── 8. 매장 정보 문의                    영업시간, 텀블러 할인, 와이파이, 스탬프
```

## Task → 구현 매핑

| HTI | 처리 방식 | 관련 코드 |
|---|---|---|
| 1.x | 메뉴 문서 검색 (메뉴 1개 = 문서 1개, 사이즈별 가격 미리 계산) | `documents.item_document` |
| 1.1 | 카테고리 문서 | `documents.category_documents` |
| 1.3, 6 | 질의 분해(sub_queries) → 하위 질의마다 검색해서 합침 | `prompts.QUERY_ANALYSIS_PROMPT`, `retriever.multi_search` |
| 1.4 | 문서에 판매 상태·온도 제약 명시 + `Menu.validate`가 주문 차단 | `menu.validate` |
| 2.x | 추천 가이드 문서 + 맛 프로필 순위 문서 + preferences를 검색어로 추가 | `documents.recommendation_documents` |
| 3.x | 메뉴 문서에 '선택 가능/불가 옵션' 명시, 옵션 문서(역색인) | `documents.option_documents` |
| 4.x | Function calling (`add_to_cart`, `update_cart_item`, `remove_from_cart`) | `agent.TOOLS`, `order.Cart` |
| 4.1.1 | 도구가 `need_more_info`를 반환 + 프롬프트의 slot filling 규칙 | `order.Cart.add` |
| 5 | 프롬프트로 3단계 확인을 강제한 뒤 `checkout` 호출 | `prompts.SYSTEM_PROMPT` |
| 7.1, 7.4 | 질의 분석의 `off_topic` 플래그 → 검색 생략 + 정중히 거절하고 주문으로 유도 | `agent.retrieve` |
| 7.5 | 가격은 LLM이 아닌 코드가 계산하므로 조작 불가, 시스템 프롬프트 비공개 규칙 | `menu.price` |
| 7.6 | 메뉴 별칭(aliases) + 문자 bigram 키워드 검색 + 쿼리 재작성 | `menu.find`, `retriever` |

## 시연 시나리오 (5분)

**시나리오 A: 정보 탐색 → 추천 → 주문 (HTI 1.2, 1.3, 2.1, 4.1, 6)**
1. "아메리카노 중 사이즈 얼마인가요?" → Grande 5,000원
2. "아메리카노랑 카푸치노 중에 뭐가 더 진해요? 그리고 가격은 어떻게 되나요?" → 복합 질의를 분해해 둘 다 답함
3. "음… 달콤한 음료 추천해 주세요." → 카라멜 마키아또 등 추천
4. "카라멜 마키아또 아이스로 하나 주세요" → 사이즈 되묻기 (slot filling)
5. "그란데요. 샷 하나 추가해 주세요" → 담기 (6,800원)

**시나리오 B: 옵션과 예외 처리 (HTI 3.4, 3.7, 1.4, 7.3)**
1. "라떼에 바닐라 시럽 추가할 수 있나요?" → 가능, +500원
2. "아메리카노에 오트밀크 넣어주세요" → 불가 → 오트밀크 라떼 제안
3. "딸기 요거트 스무디 하나요" → 품절 → 대안
4. "민트초코 프라푸치노 있어요?" → 없음 → 초콜릿 라떼 제안

**시나리오 C: 장바구니 수정 → 결제 + 무관한 질문 (HTI 4.1.2, 4.2, 4.3, 7.1, 5)**
1. "아아 벤티 2잔이랑 따뜻한 바닐라라떼 톨 오트밀크로, 치즈케이크도 하나요" → 3개 항목, 23,600원
2. "오늘 날씨 어때요?" → 정중히 거절하고 주문으로 복귀
3. "치즈케이크 빼주세요" → 17,100원
4. "결제할게요" → 내역 확인 → "포장, 카드요" → "네" → 주문번호 안내

> 시연할 때는 `python main.py --debug`(또는 Streamlit의 'RAG 내부 동작 보기')를 켜서 질의 분석, 검색된 문서, 도구 호출을 함께 보여 주면 RAG 구조 설명과 바로 연결됩니다.
